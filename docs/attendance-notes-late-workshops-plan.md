# תוכנית: הערה בנוכחות, איחור ויציאה מוקדמת, ונוכחות פרטנית בסדנאות

> מסמך תכנון בלבד. אין בו שינויי קוד.
> תאריך: 14.10.2026

## 1. מטרות

1. **הערה קצרה בסימון נוכחות:** שורה אחת, אופציונלית, שלא מאטה את הסימון הרציף. הערה שנרשמה נראית במקומות הנכונים, בצורה עדינה.
2. **איחור ויציאה מוקדמת:** סימון מהיר, עם שעה ועם הערה אם רוצים, שמופיע בסטטיסטיקות כדי שאפשר יהיה לעקוב.
3. **נוכחות פרטנית בסדנאות:** סימון לכל מפגש בנפרד. הסימון "חכם": נוכחות בסדנת בוקר ממלאת את הנוכחות היומית, ופערים בין מפגשים מציעים "איחור" או "יציאה מוקדמת".
4. **מובייל קודם:** הקשה אחת נשארת הקשה אחת. כל השאר משני, קטן ולא מעיק.

## 2. המצב היום (מה צריך לדעת לפני שבונים)

**איך מסמנים:**
- המסך הראשי לסימון הוא `/admin/patient-attendance`. בשורה של כל משתתף (`src/components/admin/attendance/AttendanceItem.tsx`) יש שם, תווית מצב ושני כפתורים גדולים: ✗ ו-✓.
- הקשה שנייה על אותו כפתור מבטלת את הסימון, ואז המסמך נמחק.
- יש גם מטריצה חודשית (`/admin/attendance-matrix`), תצוגות קריאה בלבד (דף הבית, סקירה, יומן, פרופיל משתתף) וייצוא ל-Excel.

**הנתונים:** אוסף `attendance`, מסמך עם השדות `patientId`, `date`, `status` (`present`/`absent`), `contextId` ו-`updatedAt`.
- אין שדה הערה, אין מי סימן, ואין שעות.
- "איחור" קיים רק כטיפוס TypeScript (`patients/[id]/page.tsx:79`), בלי מקום שכותב אותו.
- יציאה מוקדמת לא קיימת בכלל.

**סדנאות:** מפגשים לא נשמרים כמסמכים. הם נגזרים מ-`workshops` + `session_changes` + `closures` (`src/lib/workshops/buildWeek.ts`).
- המזהה של מפגש הוא `${workshopId}_${date}_${slotId}` (`changeIdFor`), ולמפגש חד-פעמי יש מזהה אקראי.
- רשימת המשתתפים במפגש מחושבת ב-`src/lib/workshops/people.ts`.
- **אין היום שום נוכחות לרמת מפגש.** בתוכנית היומן (`docs/schedule-redesign-plan.md`, סעיף 11) כבר מתוכנן כפתור "סמן נוכחות" בגיליון המפגש, ומונה "N חסרים" בכרטיס.

### בעיות קיימות שהתוכנית חייבת לפתור קודם
| # | בעיה | למה זה חוסם |
|---|---|---|
| א | **מזהה מסמך הנוכחות תלוי במסך.** `patient-attendance` כותב `${patientId}_${groupId/programId}_${date}`, והמטריצה כותבת `${patientId}_${hosenType\|\|"general"}_${date}`. לאותו משתתף באותו יום יכולים להיות שני מסמכים, וכל מסך מציג מצב אחר | הערה, איחור או מילוי אוטומטי שנכתבים למסמך אחד לא ייראו במסך אחר, והסטטיסטיקה תספור כפול או תחסיר |
| ב | **מי "שייך לקבוצה" מחושב אחרת בכל מסך:** `hosenType` מול `groupIds`, `programId` מול `programIds` | מונה "חסרים" במפגש לא יתאים למונה היומי |
| ג | **כללים:** `match /attendance` מתיר כתיבה לכל משתמש מחובר (`allow write: if isAuthenticated()`), כולל משתתף | הערות ואיחורים הם מידע רגיש. אסור שמשתתף יוכל לכתוב או לקרוא אותם |
| ד | **משתתף יכול לקרוא את מסמך הנוכחות של עצמו** (לפי הכללים) | אם ההערה תישמר באותו מסמך, המשתתף יראה אותה. כללי Firestore לא יכולים להסתיר שדה בודד |

## 3. מודל נתונים

### 3.1 נוכחות יומית: מסמך אחד למשתתף ליום
- **מזהה קבוע:** `attendance/{patientId}_{yyyy-MM-dd}`, בלי `contextId` במזהה. ה-`contextId` נשאר שדה מידע בלבד (מאיזה מסך או קבוצה סומן).
- **שדות חדשים:**

```
status:     "present" | "absent"          // ללא שינוי. איחור ויציאה מוקדמת = נוכח + סימון
late?:      { at?: "HH:MM" }              // הגיע באיחור. השעה אופציונלית
leftEarly?: { at?: "HH:MM" }              // יצא מוקדם. השעה אופציונלית
hasNote?:   boolean                       // רק דגל, כדי שמסכים יידעו להציג אינדיקציה בלי לקרוא את ההערה
source?:    "manual" | "session"          // "session" = מולא אוטומטית מסימון בסדנה (סעיף 6)
derivedFrom?: string                      // מזהה המפגש שממנו מולא
updatedBy:  uid
updatedAt:  timestamp
```

- **מצב בלי סימון ועם הערה** ("הודיע שיאחר"): המסמך נשאר עם `status: "unset"`. כל הקוראים כבר מסננים `unset`. ביטול סימון ימחק את המסמך רק אם אין לו הערה.

### 3.2 הערות: אוסף נפרד שרק צוות קורא
`attendance_notes/{attendanceId}`, כאשר `attendanceId` הוא אותו מזהה של מסמך הנוכחות, או של מסמך נוכחות המפגש (סעיף 3.3).

```
text:      string  (עד 80 תווים, שורה אחת)
patientId, date, kind: "day" | "session"
updatedBy, updatedAt
```
הסיבה להפרדה היא בעיה ד: משתתף שמחובר לאפליקציה רשאי לקרוא את מסמך הנוכחות שלו, אבל לא את ההערה. את אוסף ההערות רק צוות קורא.

### 3.3 נוכחות במפגש
`session_attendance/{sessionId}_{patientId}`, כאשר `sessionId` הוא אותו מזהה שהיומן כבר משתמש בו (`changeIdFor`, או המזהה של מפגש חד-פעמי).

```
patientId, date, workshopId, slotId | null, programId
status:     "present" | "absent"
late?:      { at?: "HH:MM" }      // הגיע למפגש באיחור
leftEarly?: { at?: "HH:MM" }      // יצא מהמפגש לפני הסוף
hasNote?:   boolean
updatedBy, updatedAt
```

### 3.4 כללים (חלק מהשלב הראשון)
- `attendance`, `session_attendance`: קריאה לצוות. משתתף קורא רק את המסמכים שלו (כמו היום). **כתיבה לצוות בלבד** (`isStaff()`), עם בדיקת שדות: `status` מתוך הרשימה המותרת, `note` לא נשמר כאן, ושעות בפורמט `HH:MM`.
- `attendance_notes`: קריאה וכתיבה לצוות בלבד, ו-`text.size() <= 80`.
- בדיקות כללים נוספות ל-`tests/firestore.rules.test.ts` הקיים. ה-CI כבר מריץ אותן ופורס.

## 4. הערה קצרה בסימון (מטרה 1)

### במסך הסימון
- **בלי שינוי בזרימה:** ✗ ו-✓ נשארים במקום, באותו גודל, והקשה עליהם לא פותחת שום דבר.
- **כפתור הערה עדין:** אייקון בועה קטן (32px, בצבע מושתק), צמוד לשם בצד הנגדי לכפתורי הסימון, כדי שלא ילחצו עליו בטעות תוך כדי סימון רציף.
- **הקשה על הבועה:** נפתחת מתחת לשורה עצמה שורת קלט אחת. בלי מודאל ובלי לעזוב את הרשימה.
  - `maxLength=80`, `enterKeyHint="done"`.
  - Enter או יציאה מהשדה שומרים, ו-Esc מבטל.
  - השמירה אופטימית: השורה מתעדכנת מיד, וכשל מחזיר את הקודם עם הודעה קטנה.
- **הערות מוכנות (אופציונלי):** מעל המקלדת 3 עד 4 צ'יפים מהירים, למשל "הודיע מראש", "מחלה", "תור לרופא", "הגיע עם מלווה". הקשה על צ'יפ ממלאת את השדה. את הרשימה אפשר לערוך בהגדרות.
- **הערה שכבר נרשמה:** שורה אחת מתחת לשם, במקום תווית המצב או לידה. אייקון בועה קטן וטקסט מושתק בגודל 11px, שנחתך ב-`…`. הקשה פותחת לעריכה.

### איפה עוד רואים הערה (בצורה לא מעיקה)
| מקום | תצוגה |
|---|---|
| מטריצה חודשית | נקודה קטנה בפינת התא. במחשב נגיעה או ריחוף מציגים את ההערה, ובמובייל הקשה ארוכה |
| פרופיל משתתף, לשונית נוכחות | ברשימת התאריכים, ההערה מתחת לתאריך בשורה אחת |
| סקירה יומית (`/attendance/overview`) | ליד שמות הנעדרים, ההערה בסוגריים ובצבע מושתק |
| יומן נוכחות (`/attendance/log`) | עמודת הערה |
| ייצוא Excel | לשונית "הערות": תאריך, משתתף, סוג (יום או מפגש) והערה. התאים בטבלה הראשית לא משתנים |

## 5. איחור ויציאה מוקדמת (מטרה 3)

### סימון בלי להעמיס
- **"נוכח" נשאר הקשה אחת.** איחור ויציאה מוקדמת הם תוספת לנוכחות, לא מצב שלישי, ולכן אין כפתור שלישי בשורה.
- **הקשה ארוכה על ✓** (או על השורה) פותחת גיליון תחתון קטן לאותו משתתף:
  - **צ'יפים גדולים:** "נוכח", "איחור", "יצא מוקדם", "נעדר".
  - **שעה, אופציונלית:** "עכשיו" (ברירת מחדל), "‎+15 דק׳", "‎+30 דק׳", או בחירת שעה. אפשר לשמור גם בלי שעה.
  - **הערה:** אותה שורה אחת מסעיף 4.
- **גם בלי הקשה ארוכה:** בגיליון יש לכל שורה כפתור "⋯" קטן. ההקשה הארוכה היא קיצור דרך, לא הדרך היחידה, כי לא כולם מגלים אותה.
- **יציאה מוקדמת בדרך כלל מסומנת אחר הצהריים**, ואז אין צורך לחפש: בראש הרשימה יש סינון "נוכחים היום" ופעולה ישירה "יצא מוקדם".

### תצוגה
- **תג קטן ליד השם:**
  - `⏱ 09:40` בכתום מושתק לאיחור.
  - `↩ 12:15` לאפור לכחלחל ליציאה מוקדמת.
  - בלי שעה התג הוא "איחור" או "יצא מוקדם".
- **אחוזי נוכחות:** איחור ויציאה מוקדמת **נספרים כנוכחות.** הם מונים נפרדים ולא מורידים מהאחוז.

### סטטיסטיקות
| מקום | מה מוסיפים |
|---|---|
| דף הבית (StatRow) | "איחורים היום", רק כשיש לפחות אחד, כדי לא להוסיף כרטיס ריק |
| מסך הסימון | בכרטיס הסיכום: נוכחים · נעדרים · ממתינים, ושורה מושתקת "3 איחורים · 1 יצא מוקדם" |
| פרופיל משתתף | ספירת איחורים ויציאות מוקדמות בחודש ובכל התקופה, ממוצע דקות איחור (כשיש שעות), ורשימה עם הערות |
| סקירה יומית | לכל קבוצה: נוכחים / סה״כ, איחורים, יצאו מוקדם |
| מטריצה + Excel | בתא: "+" לנוכח, "+א" לאיחור, "+י" ליציאה מוקדמת. בסוף כל שורה עמודות "איחורים" ו"יציאות מוקדמות" לחודש |
| התרעה עדינה | משתתף עם 3 איחורים ומעלה בשבועיים מקבל סימון בפרופיל ובסקירה. בלי התראה קופצת. הסף ניתן להגדרה |

## 6. נוכחות פרטנית בסדנאות (מטרה 2)

### איפה מסמנים
- **בגיליון המפגש ביומן** (`/schedule`): כפתור "סמן נוכחות", כמו שתוכנן ב-`schedule-redesign-plan.md` סעיף 11. הוא נפתח כגיליון תחתון עם רשימת המשתתפים במפגש (מ-`people.ts`), מקובצת לפי קבוצה.
- **בדף הבית** (`TodaySchedule`): למי שמשובץ כצוות במפגש שמתחיל או מתקיים עכשיו מופיע כפתור "סמן נוכחות" ישירות בכרטיס.
- **אותו רכיב שורה** (`AttendanceItem`) בגרסה קומפקטית, עם אותם ✗ / ✓, אותה הערה ואותו גיליון איחור, כך שאין מה ללמוד מחדש.

### מה הופך את זה ל"חכם"
1. **נוכחות במפגש ממלאת את הנוכחות היומית:**
   - משתתף שסומן "נוכח" במפגש כלשהו ביום, ועדיין אין לו סימון יומי, מקבל אוטומטית `status: "present"`, `source: "session"`, `derivedFrom: <sessionId>`.
   - שתי הכתיבות יוצאות ב-`writeBatch` אחד.
2. **ביטול מסודר:** ביטול סימון במפגש מבטל את המילוי האוטומטי, רק אם הנוכחות היומית עדיין `source: "session"` מאותו מפגש, ואין מפגש אחר שבו הוא נוכח. סימון ידני אף פעם לא נדרס.
3. **סימון יומי ממלא מראש את המפגש:**
   - בפתיחת גיליון המפגש, מי שסומן "נעדר" היום מופיע מסומן נעדר ומעומעם. אין צורך לסמן אותו שוב, אבל אפשר לשנות.
   - כפתור "כולם הגיעו" מסמן נוכח את כל מי שלא סומן. זה הכפתור הכי שימושי בפועל: מסמנים חריגים, ולוחצים פעם אחת על השאר.
4. **הצעות לאיחור ויציאה מוקדמת, בלי לכתוב אוטומטית:**
   - **איחור:** נעדר במפגש הראשון של היום ונוכח במפגש מאוחר יותר, או שסומן נוכח יותר מ-10 דקות (ניתן להגדרה) אחרי תחילת המפגש. מוצעת הודעה קטנה: "איחור? הגיע ב-10:30 [סמן]". **לא נכתב אוטומטית,** כי שעת הסימון היא לא שעת ההגעה.
   - **יציאה מוקדמת:** נוכח במפגש בוקר ונעדר במפגש מאוחר יותר באותו יום. מוצעת אותה הודעה עם "יצא מוקדם?".
   - הצעה שנדחתה לא חוזרת לאותו משתתף באותו יום.
5. **סתירה בין יום למפגש:** אם המשתתף סומן "נעדר" ביום אבל נוכח במפגש, הנוכחות היומית לא משתנה. בשני המסכים מופיע תג "סתירה" עם תיקון בהקשה אחת: "עדכן לנוכח".

### תצוגה ביומן
- **כרטיס המפגש:** "12" לפני שמסמנים, "12 · 2 חסרים" אחרי. בלי צבעים חדשים.
- **אחרי שעת הסיום:** מפגש שעבר ולא סומנה בו נוכחות מקבל נקודה מושתקת קטנה, לפי בחירה (סעיף 9).

### סטטיסטיקות סדנאות
- **בעורך הסדנה** (`/admin/workshops/[id]`), לשונית "נוכחות":
  - אחוז נוכחות לכל מפגש.
  - לכל משתתף: מפגשים שהשתתף בהם / משובץ, איחורים, יציאות מוקדמות.
  - ההערות של המפגשים.
- **בפרופיל המשתתף:** פירוק לפי סדנה, למשל "אומנות 8/10, ספורט 5/9".
- **ייצוא Excel:** לשונית לכל סדנה, עם שורות משתתפים ועמודות מפגשים.

## 8. בדיקות
- **יחידה:**
  - מילוי יומי מתוך מפגש: מילוי, ביטול, שני מפגשים, ומילוי שלא דורס סימון ידני.
  - הצעות: איחור לפי מפגש ראשון, איחור לפי שעת התחלה עם סף, יציאה מוקדמת.
  - מיגרציה: איחוד כפילויות.
- **כללים** (בחבילה הקיימת):
  - משתתף לא כותב ולא קורא הערות.
  - עובד כותב נוכחות.
  - הערה של יותר מ-80 תווים נדחית.
  - `status` לא חוקי נדחה.
- **ידני במובייל:**
  - סימון רציף של 20 משתתפים בלי פתיחת שום דבר בטעות.
  - הערה מהירה עם מקלדת פתוחה, בלי שהרשימה קופצת.
  - הקשה ארוכה לעומת "⋯".
  - מפגש ביומן: "כולם הגיעו" ושני חריגים.

## 9. החלטות פתוחות
1. **נוכחות יומית: למשתתף או למשתתף + קבוצה?** ההמלצה היא מסמך אחד למשתתף ליום, כי הנוכחות לפי פעילות עוברת לסדנאות. אם יש משתתף ששייך לשתי קבוצות באותו יום וצריך נוכחות נפרדת לכל אחת, צריך לדעת עכשיו.
2. **שעה באיחור וביציאה מוקדמת:** אופציונלית עם "עכשיו" כברירת מחדל (ההמלצה), או חובה?
3. **מי מסמן נוכחות במפגש:** כל איש צוות (ההמלצה, כמו היום ביומי), או רק הצוות המשובץ למפגש?
4. **סף "איחור" במפגש:** 10 דקות אחרי ההתחלה?
5. **הערות מוכנות (צ'יפים):** אילו ארבע?
6. **נקודה על מפגש שעבר בלי נוכחות:** להציג או לא?
7. **סף ההתרעה על איחורים חוזרים:** 3 בשבועיים?
